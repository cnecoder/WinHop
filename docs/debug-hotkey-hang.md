# 排障记录：全局热键一轮后失效 + 主线程卡死（2026-08-08）

## 一、问题现象

2026-08-08 晚（19:27 之后）引入。现象链条随时间推移变化：

1. **热键设置功能使用中**：设置快捷键后热键不生效；设置相同快捷键时覆盖层直接消失。
2. **热键一轮后失效**：第一次 Ctrl+Space 正常呼出/退出，第二次起无响应。
3. **鼠标响应变卡**：点击后鼠标输入迟缓（LL 钩子线程被卡）。
4. **主线程僵死**：应用整体卡死，需手动杀进程；曾连带 Windows 资源管理器崩溃（explorer.exe 退出，桌面一起没）。

## 二、根因分析

### 结论

问题由「热键设置」功能（提交 041fe77，19:27）引入，分两层：

**第一层（功能引入的直接破坏）**：`set_hotkey` 命令使用
`app.global_shortcut().unregister_all()` + `register(new)` 重建 Tauri 插件热键表。
对插件反复注销/注册会打乱内部热键分发表，实测表现：**注册仍在、WM_HOTKEY 不再投递**。
用户按住 Ctrl+Space 点「应用」时重新注册同键，会立即触发一次 toggle（「界面直接消失」）。

**第二层（替换插件后暴露的深层问题）**：换成自建热键窗口线程后（6d4d53c），
WM_HOTKEY 正常到达热键窗口（日志证实），转发主线程后**主线程已卡死，任务永不执行**。
真实复现日志（用户键盘实测，第三次组合键）：

```
[t=1786194922241] overlay close (switched=false)
[t=1786194922241] close: hide 前
[t=1786194922259] close: hide 后     ← 之后主线程再无动静（emit 前/后 日志缺失）
```

主线程卡在 close() 的 hide() 之后、emit 之前。与 DWM/explorer 异常强相关
（explorer 崩过一次）。**主线程一卡，所有经 run_on_main_thread 转发的任务
（热键、鼠标）全部死掉**——这是热键失效的直接机制。

**为什么之前没有**：close()/hide() 路径代码在 15:57→19:27 之间一字未改
（diff 仅有 Render 加 hotkey 字段 + set_hotkey 命令）。下午全天热键稳定
（插件时代 close 跑在插件线程），19:27 热键设置功能上线后首次报障，
且报障场景就是使用该功能时。

### 附带发现的两个真 bug

1. **suppress_hotkey 死标志**（0ec851d）：全代码仅声明、写入、初始化 3 处引用，
   **从未被读取**。该提交声称「录制时吞掉热键」，但吞掉逻辑未实现——
   录制期间按全局热键仍会 toggle 关闭覆盖层。
2. **鼠标钩子线程上直接跑 close()**：mouse_proc 的 ClickOutside 分支同步调用
   handle_key → close → hide()。LL 钩子有超时（约 1s），close 卡住时钩子线程
   也被卡 → 系统输入管线冻结 →「鼠标响应变卡」。
