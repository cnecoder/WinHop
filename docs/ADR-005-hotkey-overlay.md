# ADR-005: 全局热键与覆盖层交互

- 状态: 已废弃 (2026-08-02)，见 README「输入架构」
- 废弃原因: LL 键盘钩子方案被 Chromium raw input 推翻——Chromium 前台用 raw input 收键盘，
  WH_KEYBOARD_LL 钩子完全看不见按键。现方案: RegisterHotKey（热键）+ 覆盖层夺焦 +
  webview JS keydown（覆盖层按键）。
- 关联: [[glossary]]

## 背景

覆盖层是每次操作的核心 UI，热键与按键路由决定整体手感。中文输入法（IME）开启时会劫持字母键输入，这是 Win10 下覆盖层必须解决的关键问题。

## 决策

**全局热键**：默认 `Ctrl+Space`（Win 下基本无冲突），配置可改。用 `global-hotkey` crate 注册。热键再按 = 关闭覆盖层（toggle）。

**覆盖层显示**：固定主屏，borderless、topmost 半透明浮层，列表式布局（每行：字母 + 程序名 + 屏幕标签，见 ADR-003）。第二层每行：编号 + 窗口标题 + 屏幕标签。未运行条目灰色。

**按键路由：低级键盘钩子**。覆盖层打开时注册 `WH_KEYBOARD_LL` 低级键盘钩子，在 Rust 侧截取按键并路由，事件不落入 webview 的 IME 流程。理由：
- Tauri webview 内 JS keydown 会被中文输入法组合输入劫持（字母键变成拼音输入）
- 钩子先于 IME 收到按键，可保证字母/数字/ Esc 键 100% 命中，不依赖 UI 焦点

**交互规则**：
- Esc 逐层回退（第二层→第一层→关闭）
- 再按全局热键 = 关闭
- 点击覆盖层外部（另一屏幕区域）= 关闭
- 不自动关闭（用户明确选择，误呼出靠热键 toggle 或 Esc 退出）
- 选择后立即关闭覆盖层并把焦点交还给目标窗口

**常驻**：托盘常驻，窗口关闭按钮收托盘不退出；`autostart` 可选开机自启（ADR-004）。

## 后果

- 低级钩子保证按键路由稳定，但钩子与 webview UI 之间需定义清晰的消息通道（hotkey → 状态机 → UI 更新）
- 键盘状态机（空闲→程序层→窗口层）放 Rust 侧，UI 只做渲染
- 点击外部关闭需监听鼠标，钩子只处理键盘，鼠标用窗口失焦或低级鼠标钩子辅助实现
